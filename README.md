# Offline CIDR Summarizer

Paste any text containing IP addresses and get back a compact list of CIDR blocks, ready to use as an IP allowlist (for example, an Elastic Cloud traffic filter ruleset).

> [!IMPORTANT]
> **100% offline. Everything runs in your browser.**
>
> Offline CIDR Summarizer is a single, self-contained HTML file. It has no server, no backend, no analytics, no external scripts, fonts or stylesheets, and it makes no network requests. The IPs you paste never leave your machine.
>
> If you're unsure, **download `cidr-summarizer.html` and open it locally**, even with your network disconnected. It works exactly the same.

---

## Quick start

- Option 1: Access the hosted [demo page here](https://rseldner.github.io/offline-cidr-summarizer/cidr-summarizer.html)
- Option 2: Download `cidr-summarizer.html` (or clone this repo).

1. Paste your IPs and click **Analyze**.
2. Pick an output format and click **Copy output**.


## Verifying that it's offline

You don't have to take our word for it:

- **Run it disconnected.** Turn off Wi-Fi or unplug your network, then open the local file. Everything works.
- **Watch the Network tab.** Open your browser's developer tools (F12), go to the Network tab, and use the tool. The only request is the HTML file itself.
- **Read the source.** It's one file of plain HTML, CSS and JavaScript with no dependencies and no minification. Searching it for `http`, `fetch`, `XMLHttpRequest` or `<script src` turns up nothing.

## Paste anything

You don't need to clean up your input. The tool pulls IPv4 and IPv6 addresses, CIDRs and ranges out of any text (emails, tickets, logs, spreadsheets) and ignores everything else.

```text
Hi team, please allow 10.0.0.1, (10.0.0.2) and 10.1.0.0/16.
- 172.16.0.1 - 172.16.0.50
src=[2001:db8:0:1::5]:443 and 2001:db8::1, 2001:db8::2
client ::ffff:198.51.100.9 at 12:30:45 via fe80::1%eth0
```

| Recognized | Examples |
|---|---|
| IPv4 addresses | `10.0.0.1`, `(10.0.0.2)`, `ip=10.0.0.3`, `10.0.0.4:443`, `10.0.0.5.` at the end of a sentence |
| IPv4 CIDRs | `192.168.0.0/24` |
| IPv4 ranges | `172.16.0.1-172.16.0.50`, `172.16.0.1 - 172.16.0.50`, en or em dash |
| IPv6 addresses | `2001:db8::1`, full or shortened forms, any case, `[2001:db8::1]:443`, `fe80::1%eth0` |
| IPv6 CIDRs and ranges | `2001:db8::/48`, `2001:db8::1 - 2001:db8::ff` |
| IPv4-mapped IPv6 | `::ffff:198.51.100.9` is treated as the IPv4 address `198.51.100.9` |

Ignored: ordinary words, times like `12:30:45.123`, MAC addresses, version strings like `1.2.3.4.5`, and code like `std::vector`.

Anything that looks like an address but isn't valid (`300.1.2.3`, `10.0.0.0/33`, `2001:db8::1::2`, a reversed range) is skipped and listed so you can check it.

## Settings

### Aggression

Controls how eagerly addresses are merged into larger blocks. A block is kept whole, instead of being split in half, once the share of it covered by your input reaches the threshold.

| Level | Fill needed | Behavior |
|---|---|---|
| 1 | 100% | Exact: only fully covered blocks, so no extra addresses |
| 2 | 50% | Very conservative |
| 3 | 25% | Conservative |
| 4 | 10% | Moderate |
| 5 | 3% | Balanced (default) |
| 6 | 1% | Aggressive |
| 7 | 0.3% | High |
| 8 | 0.1% | Very high |
| 9 | 0.01% | Maximum |
| 10 | 0% | Extreme: one tight enclosing block per Broadest-prefix block |

Addresses that end up in a block but weren't in your input are reported as **collateral**, so you can see exactly what a looser setting costs.

> [!TIP]
> For a security allowlist, start at level 1 to 3 and loosen only if you need fewer rules.

### Prefix limits

Set separately for IPv4 and IPv6.

| Setting | IPv4 default | IPv6 default | Meaning |
|---|---|---|---|
| Broadest / | `8` | `32` | Never output a block broader than this, and never merge across this boundary |
| Narrowest / | `32` | `64` | Never output a block narrower than this |

**About the IPv6 /64 default:** at Narrowest /64, each IPv6 address is widened to its whole /64 network. Devices often change their own address within their /64 (privacy addresses), so an exact address allowed today may stop matching later. Set IPv6 Narrowest to `128` if you want exact addresses. While widening is on, fill and collateral are counted in /64 networks rather than raw addresses.

## Output formats

- **CIDR list:** one block per line.
- **CSV:** `cidr,network,prefix,total_hosts,matched_ips,fill_pct,family`
- **Elastic JSON:** a request body for the Elastic Cloud traffic filter API, `POST /api/v1/deployments/traffic-filter/rulesets`:

```json
{
  "name": "cidr-summarizer-ruleset",
  "type": "ip",
  "region": "REPLACE_WITH_DEPLOYMENT_REGION",
  "include_by_default": false,
  "description": "Generated by Offline CIDR Summarizer: 2 rules",
  "rules": [
    { "source": "10.0.0.0/30", "description": "2 of 4 addresses from input" },
    { "source": "172.16.0.0/26", "description": "50 of 64 addresses from input" }
  ]
}
```

Set `name` and `region` before sending. Nothing is sent anywhere by the tool; you copy the JSON and send it yourself.

> [!NOTE]
> **IPv6 and Elastic Cloud:** Elastic Cloud Hosted and Serverless IP filters accept IPv4 sources only. Elastic Cloud Enterprise (ECE) accepts IPv6 addresses and CIDRs. The tool shows a notice whenever the output contains IPv6 rules.
>
> - [Manage IP filters in ECH or Serverless](https://www.elastic.co/guide/en/cloud/current/ec-traffic-filtering-ip.html)
> - [IPv6 support on ECE](https://www.elastic.co/docs/deploy-manage/deploy/cloud-enterprise/ece-ipv6-support)
> - [Create traffic filter ruleset API](https://www.elastic.co/docs/api/doc/cloud/operation/operation-create-traffic-filter-ruleset)

## How it works

1. **Extract:** regular expressions find address-like text; each match is strictly validated.
2. **Store as ranges:** every input becomes a `[start, end]` range and overlapping ranges are merged. Addresses are never listed out one by one, so a `/8` or even `::/0` takes a few bytes.
3. **Group:** ranges are grouped by their Broadest-prefix block, so no output block crosses that boundary.
4. **Split top-down:** each group starts from its tightest enclosing block. A block is kept if its fill meets the aggression threshold (or it has reached Narrowest); otherwise it's split in half and each half is checked the same way.

All math uses JavaScript `BigInt`, so one engine handles both 32-bit IPv4 and 128-bit IPv6.

### Performance

Measured in Chromium:

| Input | Time | Peak memory |
|---|---|---|
| `0.0.0.0/0` or `::/0` | ~1 ms | ~2 MB |
| 100,000 random IPv4 addresses | ~0.2 s | ~30 MB |
| 100,000 random IPv6 addresses | ~0.5 s | ~54 MB |
| 200,000 mixed IPv4 and IPv6 | ~0.6 s | ~53 MB |

Memory grows with the number of entries you paste, not with the size of the ranges.

### Limits

- The result is capped at **50,000 CIDR blocks**. Past that, the tool asks you to raise aggression or adjust the prefix limits instead of building a list too long to use.
- The results panel shows the first 1,000 blocks; **Copy output** always includes all of them.

## Browser support

Any current version of Chrome, Edge, Firefox or Safari (16.4 or later). The page needs `BigInt` and regular-expression lookbehind, which all of these support.
